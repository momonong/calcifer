# P1-A single-worker workflow (mock only)

This entry accepts a caller-owned goal and fresh small Node ESM snapshot. It does not choose a solution from a task ID. The official OpenCode or Pi SDK chooses tools from fixture HTTP model responses; that verifies workflow mechanics, not autonomous model ability.

```sh
node src/p1-cli.mjs run --repo /absolute/taskboard-cli --config /absolute/host.json --state-root /absolute/state --goal 'Implement the requested behavior and verify it' --harness opencode --profile mock-loopback --mock-script /absolute/provider.json
node src/p1-cli.mjs reopen --state-root /absolute/state --run-id UUID
node src/p1-cli.mjs export --state-root /absolute/state --run-id UUID > result.patch
```

Use `--goal-file /absolute/goal.txt` instead of `--goal`. Ctrl-C stops dispatch and the active process. Run outputs JSON including a host-derived human-readable `summary`; the same text is saved as `summary.md` and verified on reopen. Export writes a standard patch to stdout and a JSON receipt to stderr. Reopen and export never create SDK sessions, execute checks or issue provider requests.

Host configuration (outside worker snapshot):

```json
{
  "schemaVersion": 1,
  "stateRoot": "/absolute/state",
  "sourceFiles": ["AGENTS.md", "README.md", "package.json", "src/taskboard.mjs", "src/cli.mjs", "test/contract.test.mjs", "data/tasks.json"],
  "readPaths": ["AGENTS.md", "README.md", "package.json", "src/taskboard.mjs", "src/cli.mjs", "test/contract.test.mjs", "data/tasks.json"],
  "writePaths": ["README.md", "src/taskboard.mjs", "test/contract.test.mjs"],
  "createPaths": ["src/status.mjs"],
  "commands": {"test": {"argv": ["--test", "test/contract.test.mjs"], "timeoutMs": 1500}},
  "acceptance": {"scriptPath": "/absolute/protected-host-acceptance.mjs", "timeoutMs": 2000},
  "limits": {"maxToolCalls": 32, "maxOutputBytes": 32768}
}
```

`cancellation.commandProcesses` derives closure only from durable command intents and explicit close receipts; an unsettled process never appears closed because a checks list is empty. The config binds the canonical state root: a different `--state-root` is rejected. New jobs/sessions for the same repo and authority remain blocked by unresolved durable intents or locks. Changing host authority is not reconciliation or resume. Writable existing files require an expected SHA-256; creation uses an exact separate allowlist and exclusive creation. Repository instructions are context only. Host acceptance lives outside the repo and is copied/hash-bound before dispatch; the worker cannot edit or request it.

Tools: `calcifer_tool({action,args})`; `read {path}`, `search {query}`, `edit {path,expectedHash,content}`, `create {path,content}`, `check {checkId}`. Only host-registered command IDs run. Commands are Node argv arrays (no shell), in a Linux user/network/filesystem namespace with a read-only copy of the current snapshot, empty environment and bounded process/output. No fallback to unrestricted host execution.

The mock script is explicit fixture input: `{ "schemaVersion": 1, "responses": [...] }`, with each response containing text or tool calls; HTTP failures/partial streams/delays are fixture modes. It is not generated by matching the goal. No real endpoint, credential or paid fallback is supported.

Saved metadata, hash-chained intents, wire/native evidence, initial/work/final snapshots, acceptance results, summary and patch can be reopened and verified. Accepted checks bind the final manifest; source preservation and artifact membership/hashes are rechecked. UNKNOWN is terminal for this P1 entry. P1-A does not provide full resume, production hostile-code sandboxing, arbitrary project support, model quality validation or UI. P1-B requires later authorization.

## Reproducible fresh example

Run from this Calcifer worktree (Linux with the existing pinned dependencies and Node 22):

```sh
node fixtures/taskboard-cli/prepare.mjs --directory /tmp/calcifer-p1-example --case t1
node src/p1-cli.mjs run --repo /tmp/calcifer-p1-example/taskboard-cli --config /tmp/calcifer-p1-example/host.json --state-root /tmp/calcifer-p1-example/state --goal-file /tmp/calcifer-p1-example/goal.txt --harness opencode --profile mock-loopback --mock-script /tmp/calcifer-p1-example/provider.json
```

Use a new directory and `--case t2` for the red-to-green deadline regression; select `--harness pi` for the same host contract with Pi. Preparation refuses an existing destination, copies only synthetic fixture data and writes a host config with the correct absolute paths. The returned `runID` can be used with `reopen` and `export`; accepted patch content represents the saved final snapshot and never applies changes to the source repo.

Limits reuse the existing mock policy: one worker, one concurrent request, at most 6 worker requests, 512 configured output tokens per request, 10-second request deadline, 120-second dispatch window, bounded tool/file/output sizes and command deadlines. SDK settlement is separately bounded at 20 seconds. A mock fixture's content is synthetic and is not a token-quality measurement. A failed/truncated/unknown SDK result is never host acceptance.

Context includes the external goal, root AGENTS.md (when present), authorized file manifest and exact scope. Other relevant files are loaded through the scoped read/search tools. Commands run with read-only snapshot mounts; T1 permits relevant public-test edits, while T2 protects its regression file; host acceptance is protected and independently run. Checks for an unchanged manifest and definition are reused; a distinct host acceptance is still required. Repeated worker reads/checks are observable in native tool records and metrics, not evidence of autonomous strategy.

## Known failures and interrupted runs

An authorized read of a not-yet-created file returns known `FILE_NOT_FOUND`; it does not seal the authority as UNKNOWN. A registered noisy command that was stopped and observed closed returns known `CHECK_OUTPUT_LIMIT`. The SDK receives a bounded serialized summary with an explicitly truncated preview; the host retains complete capped output as lossless base64 plus raw-byte SHA-256 and a human-readable decoded representation. Reopen verifies original bytes, including invalid UTF-8 or a multibyte character cut at the output cap.

`sourcePreserved` is `null` until the source comparison runs, `true` for an observed match, and `false` only for an observed mismatch. T2 fixture contracts omit the regression file from `writePaths`; T1 can edit its relevant public test. Checks with the same manifest and definition reuse known results, including failure, rather than rerunning unchanged work.

If a child dies before producing a terminal report, reopen still returns the verified metadata/ledger status (`unknown` or `incomplete`), no accepted artifacts and no resumed work. Available initial files are checked against the recorded manifest; missing or partially initialized snapshots are explicitly marked absent/partial. Other unfinished evidence remains unverified. No report, receipt, lock or source file is created or repaired by reopen.

Both final retained SDK examples passed source-preservation, read-only reopen/export and patch `apply --check`.
