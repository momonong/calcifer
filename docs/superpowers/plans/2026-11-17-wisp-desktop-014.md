# Wisp 0.1.4 desktop alignment implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan in the existing isolated worktree. Preserve the original working tree and runtime evidence.

**Goal:** Align the Ubuntu desktop with the already installed Hermes 0.23.2, make the configured `wisp` command open that desktop, and merge the verified source changes.

**Architecture:** Keep the official Hermes source unchanged. Build a separate pinned desktop, reuse the existing Wisp profile, and add optional desktop configuration to the existing launcher. Configurations without a desktop retain Webapp behavior.

**Tech Stack:** Python standard library launcher, official Electron desktop, pinned Node/pnpm, existing unittest suite.

**Spec:** The approved maintenance requirements below. This is not Phase 1.

## Approved requirements

- Preserve login, Hermes configuration, projects, conversations, original worktrees and old releases.
- Align the desktop to Hermes `v0.23.2`, commit `ae2a81ccc00e9b7c06301523e5bb09608397149c`.
- On the configured Ubuntu installation, `wisp` opens Desktop; `wisp webapp` explicitly opens the browser.
- Keep Windows on its verified Webapp/0.23.1 engine path; no claim of Windows Desktop acceptance.
- Merge and push source/docs to the existing `momonong/calcifer` repository. Exclude private runtime, credentials, conversation content and local paths from published evidence.
- Explain Wisp's actual additions separately from inherited Hermes features and unimplemented plans.

## Global constraints

- Worktree: the existing Wisp delivery checkout; base `1d458220ea651fd261745c49e7edcc32e23c20ec`.
- Wisp version `0.1.4`; do not replace the published `0.1.3` archive.
- No Hermes fork, OpenCode integration, new model routing or Phase 1.
- No change to the original Knowledge Hub or its private database.
- No automatic model requests, paid provider fallback or wholesale service restart.
- Actual native rendering is distinct from startup checks and browser validation.

## Review Focus

- Spaces/non-ASCII paths and explicit argv, without shell interpolation.
- Inherited profile/runtime/Electron overrides must not escape the Wisp profile.
- Missing desktop assets must fail visibly; no silent switch to another profile or interface.
- Reinstallation must preserve optional desktop configuration and authentication.
- Desktop startup failures must propagate; a spawned process is not a healthy UI claim.
