可以先完成 P1 範圍內的功能，不需要拿任何現有專案試。建議另建一次性的驗收 repo，先驗機制，再用真實開源模型驗工作能力。

## A 為什麼要分成兩個完成點？

| 完成點 | 要證明什麼 | 需要真實模型嗎？ |
| --- | --- | --- |
| P1-A 功能完成 | 使用者入口、工具、權限、狀態、驗證與成果交付能運作 | 不需要；使用 mock provider 與受控工具案例 |
| P1-B 工作能力驗收 | 模型能理解任務、選工具、修改、驗證並適時停止 | 需要；仍只使用獨立驗收 repo |

程式測試可以證明流程機制，不能證明開源模型會自主完成工作。這不要求修改任何既有產品，也不要求先在真實使用者資料上試錯。

這次建議先確認並開發 P1-A。完成後可如實交付「P1 功能可用、模型工作能力待驗」，不把整個 P1 或全部 40 項能力宣稱完成。

## B 用什麼專案與任務驗收？

建議建立全新的 **taskboard-cli**：讀取合成任務 JSON，列出、篩選與統計任務的命令列小程式。使用 Node ESM 與 node:test，零外部依賴；約 6–10 個小檔案。

不需要資料庫、網路服務、帳號或正式 UI。每案從固定且獨立的起始 snapshot 執行；它的用途是驗收卡西法，不是新增一個要長期維護的產品。

| 任務 | 具體交辦 | 成功條件 |
| --- | --- | --- |
| T1 小功能 | 新增 `list --status done` 篩選，補必要說明與相關測試 | 公開輸出正確；無關檔案不變；既有功能維持正常 |
| T2 修 bug | 修正截止時間篩選的邊界錯誤，涵蓋等於邊界與缺值 | 同一回歸先失敗、修改後通過；沒有刪測試或改弱斷言 |
| T3 中斷與未知結果 | 在工作途中注入已知工具失敗、取消或回應未知 | 已知失敗有原因；停止後不再派送；未知副作用不重做；重開可讀狀態 |

T3 的離線案例驗機制；真模型案例另記錄實際行為。P1 不宣稱已能從 UNKNOWN 自動恢復續作，完整 resume 留在 P3。

起始程式、任務、公開回歸與 host 邊界驗收先固定。模型可以看到一般專案測試；host 的額外驗收不由 worker 修改。真模型接手時不提供預設 patch 或預排工具動作。

## C P1-A 要補齊哪些模組？

沿用 v0.0.7 的 SDK、工具、帳本與 patch 基礎；不另造一套 agent loop。

| 模組 | 需要補齊的行為 | 對照總表 |
| --- | --- | --- |
| 交辦入口 | CLI 接受目標、repo、profile、允許範圍與驗收；不再固定 demo | M08、M35 |
| Repo 與 context | 載入指定專案、必要工程規則與相關檔案，保留既有內容 | M05、M16、M17 |
| 檔案與命令工具 | 補任務需要的檔案新增／修改、受控測試命令與程序停止 | M18、M19、M21 |
| Provider 接線 | 真正的 transport／安全設定接線，以本機 mock endpoint 驗完整請求；未批准遠端不可送出 | M01–M04、M07 |
| Worker 與完成判斷 | 同一入口使用官方 SDK，結果交由 host 核對；預算內完成或明確停止 | M11、M15、M20 |
| 權限與持久狀態 | 預授權清單、越權拒絕、取消、UNKNOWN、唯讀重開 | M23–M27 |
| 驗證與觀測 | 綁定實際修改版本，記錄測試、回合、重讀重測與人類介入 | M20、M34 |
| 成果交付 | 人可讀摘要、diff／patch、驗證、失敗與未完成項；輸出來源可核對 | M30、M31 |

這一段只要求單模型、單 worker 能完成流程。已存在的路由與 DAG 基礎保留；多模型分派成效、平行 workers、互動式擴權批准、通用套用來源與 Git 發布留待後續確認。

## D 開發與實測分別需要多少資源？

| 資源 | P1-A 功能開發 | P1-B 實測提案 |
| --- | --- | --- |
| 開發機 | 現有 Node／Bun、鎖版 SDK、合成檔案、局部必要測試 | 同一開發機執行工具與驗收 |
| GPU／模型服務 | 不需要；真實 API 呼叫 0 | 一個已授權 selfhost 開源模型；不下載權重、不自行恢復服務 |
| 資料 | 新建合成 repo；不用任何現有專案內容 | 同一合成 repo 與固定任務 |
| Harness | OpenCode 主流程；Pi adapter 共用契約測試 | 同一模型、任務、工具、預算與起始 snapshot 比較 |
| 請求數 | mock 次數不當成模型品質數據 | 合計最多 40 次，含 canary、工具續輪及可用的重試；單併發 |
| 輸出上限 | 使用小型與邊界 fixtures | 建議 canary 每次 512，工作任務每次最多 2048 tokens；這是待批准的新提案 |
| 時間與停止 | 有界命令／輸出；只補變更涉及的檢查 | 沿用 20 分鐘派送窗口提案；單請求期限須符合服務現行契約 |
| 費用 | 不新增付費 API | 使用既有資源；實際成本 unknown，沒有付費 fallback |

原批准的 40 次／每次 512 只作既有接入 smoke 邊界。上述新任務與較高輸出上限尚未獲准，不能直接套用原授權。若採提案，40 次仍是共用總上限，不另加 40 次；保守輸出預留最多 81920 tokens，不代表會用完或完成品質有保證。

可採每框架 canary 最多 2 次、三任務各最多 6 次，兩框架共最多 40 次。所有實際 provider 請求都計數，不額外增加 review 回合。T3 子情境共用該任務額度，不各自另算。

P1-A 不需等待以上 live 授權。P1-B 開始前另核對服務窗口、精確 endpoint／model／revision、parser、context、deadline 與資料／資源授權。若服務限制不相容，先交付差距，不自行調高上限或換模型。

## E 怎樣才算這段功能完成？

P1-A 的驗收針對可觀察行為，不要求新增特定測試數量。

1. CLI 可接收驗收 repo 與目標；產品不依任務 ID 回傳預設 patch 或工具順序。
2. 工具能讀檔、搜尋、做必要修改及新增檔案，執行已登錄的相關檢查。
3. T1 輸出正確；T2 有同一驗收的失敗與修復證據；無關內容不變。
4. 越權被拒；取消後停止新工作；結果未知持久保存並阻擋盲重送。
5. 重開只讀已有狀態與證據，不重新啟動 SDK、測試或模型。
6. 交付 patch、驗證與未決事項；沒有新變更或風險時不無故重測。
7. OpenCode／Pi 使用同一 host 契約；必要相容性證據分別保留。
8. 報告清楚標示 mock；不能將 P1-A 通過當成模型能力通過。

P1-B 另記錄任務正確性、驗證完整性、越界修改、重複工作理由、失敗後策略與人類介入。額度耗盡、輸出截斷或能力不足如實分開，不能一律寫成模型不會做。

## F 這次應確認的開發範圍是什麼？

**建議確認：先完成 P1-A，使用全新的 taskboard-cli 驗收 repo，不動任何現有專案；功能交付後再確認 P1-B 的服務與實測資源。**

自動模型路由仍是 P2 目標。正式 UI、完整 session resume、一般專案全技術棧支援、Spark 實機與蒸餾不納入本段。

本頁是規劃稿，沒有建立驗收 repo、實作產品、執行新測試或呼叫模型。Git 交付與私人預覽上傳仍按具體授權處理。

依據：[v0.0.7 現況與範圍](https://github.com/momonong/calcifer/blob/ee57d711760b0abf001007a2a479759ea26a15c1/README.md)、[實測與資源門檻](https://github.com/momonong/calcifer/blob/ee57d711760b0abf001007a2a479759ea26a15c1/docs/live-and-distillation-gates-2026-10-30.md)。

## 本輪實作授權與補充

使用者已明確要求開始 P1-A，完成八組功能及驗證後直接回報。只使用全新 taskboard-cli 合成 repo，不碰任何既有業務專案，不呼叫真實模型，正式 UI 暫停。P1-B 模型、服務與實測資源須另行確認。

- 從 v0.0.7 ee57d711760b0abf001007a2a479759ea26a15c1 開始；保留舊模組與同版既有證據。
- 本輪交付本機可用程式與文件；不自行 commit、push、merge、部署、改排程或服務。
- 本機 HTTP mock endpoint 只能為本次測試短暫啟動，結束關閉；不是部署服務。
- 產品不可依 task ID 或目標內容選擇預設 patch；模擬回應只存在 provider fixtures。
- 預授權檔案／命令／profile 是 host 設定，模型不能自行擴權。禁止 shell 任意字串及繼承秘密環境。
- 新檔案建立與 patch 必須可驗收；最終驗證須針對同一份成果且保護 host acceptance。
- 未知結果不能以新工作／session 清除；本輪只有安全停止與唯讀重開，不宣稱完整 resume。
- Provider 實際 HTTP 請求須走同一持久 gate；P1-A 只接受本機 mock 身分，不讀任何真實憑證或 endpoint。
