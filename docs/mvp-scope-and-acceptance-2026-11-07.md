# 卡西法 MVP：範圍、驗收與開發順序

日期：2026-11-07（Asia/Taipei）。狀態：**規格待使用者確認；只完成準備，不授權功能開發。**

## 已確認的方向

- Thor 送件優先，由目前承接 Thor 的工作繼續處理；本輪不修改 Thor、不建立重複任務。
- 卡西法先保存 MVP 範圍、驗收與開發順序，並準備既有開發環境。
- **Thor 送件完成、使用者確認本規格並明確啟動開發後，才進入實作。** 不自動監控送件或在期限後開工。
- 暫不租雲端電腦，不新增常駐服務、網路入口或正式 UI。
- OpenCode 保留主選，Pi 保留對照；其他 harness 只保留整合可能性，沒有遷移決定。
- 產品須支援任務拆解、協作、依模型與資源條件自動路由，以及手機／另一台電腦接續指定主機的對話。
- 目標是正確完成工作；Claude Code 的工作方式是研究參照，不宣稱任何模型或 harness 已普遍勝出。

本文件的模組邊界、首批案例、數量與時程是**具體待確認提案**。文件完成不代表這些功能已存在，也不等於實測、部署或 Git 發布授權。先前 P1-B 的暫停與授權條件仍有效，見 [P1-A 停止點](p1a-checkpoint-2026-10-30.md)。

## MVP 的一個完整成果

使用者交辦一個有明確完成條件的目標。卡西法讀取適用工作規則，拆出必要任務，在允許的資源中選擇執行者，保留可查的進度與收據，完成相關驗證後交付。發生已知失敗能修正假設；遇到未知結果先核對，不能藉換帳號、模型或工作階段重送。

首批驗收使用全新合成 taskboard-cli 與公開文件研究。Thor 可以提供研究問題或另行核准的合成案例，但不讓備賽時程依賴卡西法，也不直接修改正在開發的 Thor 工作樹。

驗收分成三層：離線契約成立、授權模型能完成任務、使用者能跨裝置操作。每層分別記錄，mock 通過不能代替後兩層。

## 架構與資源責任

| 層 | MVP 責任 | 邊界 |
| --- | --- | --- |
| 手機／電腦介面 | 同一對話的訊息、進度、產物、批准與停止 | 只提供操作介面；不是執行主機或憑證儲存中心 |
| 指定主機上的卡西法 | 目標、工作規則、任務依賴、權限、預算、持久狀態與驗收 | 服務必須獨立於瀏覽器生命週期；本輪不啟動 |
| Harness adapter | 使用既有公開介面執行有界工作 | 先接 OpenCode；不要求不同 harness 的原生 session 無損互換 |
| 模型資源層 | 明確模型／帳號配置、能力與用量證據；按契約接 API Broker | Broker 型錄不等於可呼叫；CLI 訂閱、API 配額與本機算力分開 |
| 本機工具與資料 | 專案檔案、Git、測試、核准外部工具 | 執行主機在本機不代表模型推論或資料一定留在本機 |

既有開發機足以準備和驗證核心。遠端入口待批准時再選用既有安全通道或常駐入口；租用 CPU 入口、雲端開發機及 GPU 是三個分開決策。執行主機睡眠或關機時不能假報工作繼續，也不自動搬移到另一台主機。

## 必做模組與可觀察條件

| ID | 模組 | 第一版的必要行為 |
| --- | --- | --- |
| M1 | 規則與目標 | 核對固定 Agent Playbook 的 SOURCE_COMMIT，完整載入核心、適用指南章節及專案 AGENTS；保存來源與完成條件。缺少必要規則時只停止受影響操作，不默默用舊版本代替。 |
| M2 | 任務拆解與協作 | 保留一個目標負責者；每項工作有依賴、輸入、寫入範圍、產物和驗收。可拆解不代表必須平行；只有無衝突且預期有收益時才並行。 |
| M3 | 模型與帳號調度 | 首批限兩個經確認可用的配置。先檢查資料與授權，再看已驗證能力，再考慮用量、重設／到期時間、時間與成本。選擇理由可查；不同帳號額度不任意加總。 |
| M4 | 程式與研究工具 | 沿用 scoped read/search/edit/check、隔離驗收與 patch；加入有界搜尋、原文讀取與一個核准唯讀 MCP。外部內容是資料，不能改寫權限或指揮執行。 |
| M5 | 權限、隱私與預算 | 主機執行資料外傳及工具限制。敏感內容、衍生摘要、diff 與 logs 都受相同規則管制。無核准本機模型時，敏感任務等待資源，不能轉送雲端。 |
| M6 | 狀態、取消與恢復 | 先保存 intent 再派送。保留 request/operation 身分與收據；已知結果可接續，UNKNOWN 保守停止並查原請求。取消分別記錄停止等待、串流 drain、工具停止與遠端推論狀態。 |
| M7 | 驗證、效率與交付 | 主機核對同一成果快照的必要驗收。沿用適用證據；新增檢查須有具體變更、風險或假設。記錄人類介入、失敗及未完成，達標後不擴張工作。 |
| M8 | 跨裝置工作階段 | 同一使用者可在兩台裝置接續同一對話。訊息可補讀、命令有唯一身分、批准綁具體操作；頁面關閉不取消任務。主機離線顯示真實狀態，裝置可撤銷。 |

M8 包含最低限度操作介面，排在核心與真實能力驗收之後；正式 UI 持續暫停。手機「從零開新對話並選主機」尚待確認，不能把前輪提問當成已批准範圍。

M1 的「完整」是完整讀取適用章節與必要專案契約；不把所有無關指南硬塞進每一個子任務。模型讀過規則也不代表規則已被執行；檔案、工具、資料與資源的硬限制由主機落實。

## 最小驗收案例

所有案例執行前保存輸入版本、允許資源、成功條件與必要驗證。下列是待批准的驗收設計，尚未執行 MVP 實測。

| 案例 | 操作與失敗注入 | 通過條件 | 層級 |
| --- | --- | --- | --- |
| A1 規則載入 | 正常載入；缺少固定指南；專案規則限制寫入 | 可列出實際讀取版本；缺項拒絕相依派送；未擴張工具權限 | 離線＋授權模型 |
| A2 小功能 | taskboard-cli 的單一有界功能 | 僅修改允許範圍；通過事先指定的相關檢查；無無關重構或整庫檢查 | 授權模型 |
| A3 Bug 修復 | 有可重現的邊界錯誤 | 保存失敗重現、修改及同一回歸通過證據；受保護驗收不被弱化 | 授權模型 |
| A4 有來源研究 | 搜尋→原文→一個唯讀 MCP→報告；注入虛構引用與頁面指令 | 重要事實可對應取得的原文／收據；推論另標；虛構引用不能算完成；不執行頁面指令 | 離線＋授權模型 |
| A5 路由與隱私 | 模型能力不符、額度過期／未知、敏感資料 | 排除不合格配置；保留選擇理由及證據時效；敏感內容不外傳；無付費 fallback | 離線＋兩個授權配置 |
| A6 分工與整合 | 兩個可拆任務、依賴及衝突結果 | 相依工作按順序；衝突不默默覆蓋；整合後對同一快照驗收 | 離線＋授權模型 |
| A7 失敗與中斷 | 已知失敗、程序中斷、送出後結果未知、取消 | 已知失敗後有可查的策略調整；已完成成果保留；UNKNOWN 不重送；重開不重設預算 | 離線＋授權模型 |
| A8 遠端接續 | 電腦與手機輪流操作、重連、重複送出、主機離線、裝置撤銷 | 同一 session 與執行主機；事件補回且無重複副作用；遠端批准與停止有回覆；離線與撤銷如實生效 | 兩個實際裝置 |
| A9 完成與預算 | 完成條件已滿足；另一案例耗盡上限 | 達標後停止新增無關工作；達上限交付部分成果及未決項；unknown usage 不當成零 | 離線＋授權模型 |

安全拒絕只證明保護成立，不等於任務已完成。例如敏感任務因無本機模型而停止，必須列為未完成；不能拿這個結果宣稱已驗證本機推論。

每次實測至少記錄 correctness、必要驗證、完整交付時間、模型回合、工具操作、重複檢查及理由、人類介入、輸入／輸出／cache usage、已知成本與失敗。缺少的用量或成本標 unknown。小樣本只支持可行性判斷。

若比較 harness，固定同一模型、任務、工具能力、預算與初始 workspace，記錄框架新增 prompt/context。若比較路由成效，另設固定配置基線；不能同時改模型、流程及任務後把差異全歸因於 harness。

## 開發順序與階段停止點

| 順序 | 交付內容與依賴 | 完成後的停止點 | 粗估有效開發時間 |
| --- | --- | --- | --- |
| D0 準備 | 本規格、環境與證據核對、待決項 | 等 Thor 送件完成及本規格確認；本輪止於此 | 0.5～1 天 |
| D1 核心串通 | 先 M1/M5/M6；以現有單任務建立完整交付路徑，再串 M2/M3/M4/M7 的必要部分 | 離線正常／拒絕／中斷案例成立；可交付明確測試候選 | 4～6 天 |
| D2 有限真實能力 | 先一個配置的工具 canary 與小任務，再加入第二配置和路由；比較研究／修 bug／恢復案例 | 達到驗收或資源上限，交付真實結果與未決項；不為耗用配額加案例 | 2～3 天 |
| D3 遠端 MVP | 核心事件與命令契約穩定後完成 M8；選定最小入口並另核對接入授權 | 手機與另一台電腦實際接續、批准、停止與重連驗收 | 3～4 天 |

合計約 10～14 個有效開發日，為規劃估算，不是日曆期限或背景連續工作承諾。D1 完成後依缺口重估；等待模型授權、主機、裝置與測試窗口另計。若 D1 需要早期真實 canary 來降低接線風險，只能提前執行已取得 D2 對應授權的部分，不能自行擴張。

每階段沿用同版本／環境／範圍的充分證據；新變更或風險才補驗。達到階段完成條件就交付，不能自動啟動下一階段。提交、推送、合併與部署各按當次明確授權處理。

## 開工與實測前一次確認

| 決策 | 接續所需內容 |
| --- | --- |
| 啟動條件 | 使用者確認 Thor 已送件、本規格範圍與下一階段；保持原對話承接 |
| 首批資源 | 兩個候選的精確 provider/model/harness/version；帳號或專案識別；安全憑證取得方式；可用窗口 |
| 資料與額度 | 允許傳送的合成／公開／私人資料；總 generation/token/費用／併發／時間上限；重試與停止規則 |
| Broker 與本機模型 | 開始該接入時重新讀現行 client-integration 契約；型錄、歷史部署或相容宣告不作可用性證明 |
| 遠端範圍 | 是否包含手機新建對話與選主機；實際手機／電腦平台；登入、通道及內容保存位置 |

先前 40 次生成上限只屬當時方案，不能挪成新供應商、帳號、多模型路由或新窗口的通用授權。未確認項目前保持 pending；使用者決定暫停的階段不是工程 blocked。

## 第一版不做

- 同時整合所有 harness、無證據的大規模多代理、一般策略引擎。
- 帳號自動註冊／登入輪換、假造跨帳號餘額、未授權模型 fallback。
- 本機模型訓練／蒸餾、下載大型權重、Spark 或 Thor 硬體驗收。
- 通用計費平台、驗證快取平台、跨主機自動搬遷或無損搬移不同 harness 的 session。
- 正式產品 UI、原生手機 App、多使用者團隊權限平台。
- 參賽報名、提交 Thor 成果、雲端採購或共用服務變更。文件的 Git 保存依另行取得的明確授權處理，不啟動功能開發。

環境與重現指令見 [MVP 開發準備與接續](mvp-readiness-2026-11-07.md)。
